# ai-guide 자동발행 — 생성 지침 (스케줄된 Claude가 매 실행마다 따름)

> 목표: **여러 매체가 전한 같은 사건을 묶어, 독자가 한 편으로 이해하는 해설 기사**를 한국어+영어로 발행한다. 양보다 질 — 하루에 몇 편 못 써도 된다.
> 한 매체 기사를 줄인 요약, 행사·홍보 글, 같은 날 이미 쓴 사건은 쓰지 않는다. 기사는 스캔되게 구조화하되 얇으면 안 된다.

## 실행 절차 (매 5시간)
1. `npm run fetch-news` 실행 → `scripts/worklist.json` 생성. 항목 하나 = 같은 사건을 다룬 출처 묶음(2개 매체 이상). 행사·티켓 홍보, 제목만 있는 항목, 오늘 이미 쓴 사건은 코드가 미리 뺀다(`src/lib/news-plan.ts`).
2. worklist가 비었으면 이번 회차는 쓰지 않는다.
3. **하루 발행 상한**(`src/lib/news-quality.ts` 의 `dailyLimit`, 환경변수 `NEWS_DAILY_LIMIT`)까지만 처리한다.
4. 각 항목 → 아래 포맷으로 **ko + en 한 쌍** 마크다운 작성:
   - `src/content/news/ko/YYYY-MM-DD-<slug>.md`
   - `src/content/news/en/YYYY-MM-DD-<slug>.md`
   - `slug`은 영어 kebab-case, 양언어 동일.
5. 처리한 원문 URL을 `scripts/_published.json`의 `urls`에 추가(중복 방지 상태).
6. `git add src/content/news scripts/_published.json` → 커밋 `feat(news): N개 다이제스트 발행` → `git push origin main`.
   - main은 Vercel git 연결됨 → 푸시 시 자동 배포.

## frontmatter 계약 (Phase 1 로더와 일치 — 반드시 준수)
```yaml
---
title: "<간결한 헤드라인 (원문 복붙 금지, 재작성)>"
lang: ko            # 또는 en
date: <YYYY-MM-DD>
slug: <kebab-slug>  # 양언어 동일
summary: "<1~2문장 요약 (meta description)>"
tags: ["LLM", "OpenAI", ...]
sources:
  - title: "<원문 제목>"
    url: "<원문 URL>"
---
```

## 본문 포맷 (★핵심 — 여러 출처를 묶은 해설, 한 줄 요약 금지)
입력은 같은 사건을 다룬 **출처 2건 이상**이다. 한 매체 기사를 줄이는 게 아니라, 출처를 견주어 독자가 한 편으로 이해하게 쓴다.
**분량 하한(코드가 검사하고 모자라면 발행하지 않는다)**: 한국어 본문 공백 제외 **800자 이상**(목표 1,000~1,400자), 영어 본문 **350단어 이상**.
분량은 출처에 없는 내용을 지어서 채우지 않는다. 출처에 있는 사실의 맥락·차이·의미를 풀어 쓰는 것으로 채운다.
```markdown
**한 줄 요약**: <무슨 일인지 1문장>

### 핵심
- <불렛 3~5개: 사실 위주, 숫자/이름 포함>

### 무슨 일이 있었나
<2~3문단: 출처별로 무엇을 전했는지 구분해서. "A는 ~라고 전했고, B는 ~라고 덧붙였다". 출처끼리 다른 점이 있으면 그대로 적는다>

### 왜 중요한가
<1~2문단: 맥락·영향. 한국 독자에게 무엇이 달라지는지가 출처에 있으면 쓰고, 없으면 지어내지 않는다>

### 더 보기
- [원문 제목](url) — 출처명   (입력으로 받은 출처 전부)
```

## 품질·정책 가드 (AdSense / 저작권)
- **원문 복붙 절대 금지.** 반드시 자기 문장으로 재작성 + 맥락 한 줄 추가(value-add).
- 출처 명시 링크 필수. frontmatter `sources` 에는 **입력으로 받은 출처 URL을 전부, 그 URL만** 적는다(다른 URL을 지어 넣으면 발행되지 않는다). 원문 전문 복제 ✗, 요약+해설+링크 ✓.
- 사실 확인: 불확실하면 단정 금지("~로 알려졌다" 톤).
- 한국어판/영어판 둘 다 작성(한쪽 누락 시 그 항목 발행 보류).
- 같은 사건 중복 발행 금지(`_published.json` + 기존 slug 확인).
- **원문 텍스트로만 쓴다 (2026-10-25).** RSS 요약에 있는 사실만 쓰고, 제목에서 내용을 추측하지 않는다. 요약이 제목뿐이면 생성기가 그 항목을 아예 넘기지 않는다(`src/lib/news-source.ts`). "보도 제목과 요약 수준", "원문에서 확인이 필요" 같은 문장이 들어간 기사는 검증에서 버려진다 — 확인할 수 없는 내용은 문장으로 사과하지 말고 쓰지 않는다.

## 톤
- 한국어: 군더더기 없는 뉴스 톤. 핵심은 불렛, 본문 해설은 문장으로.
- 영어: concise, neutral newswire tone.
- 과장·낚시 제목 금지. 정확하고 스캔 가능하게.
